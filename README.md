# limgene

欢迎加入！这个仓库目前还在初始化阶段（当前仅有占位文件），适合作为新人从 0 到 1 演练完整工程化流程。

## 如何开始（今天就能做）

1. **拉取并进入仓库**
   ```bash
   git clone <repo-url>
   cd limgene
   ```
2. **和负责人确认三件事**
   - 项目类型：CLI / Web 服务 / 库 / 数据任务
   - 技术栈：例如 Python、TypeScript、Go、Rust
   - 首个里程碑：1 周内要交付什么（可运行 demo / API / 脚本）
3. **在本地先搭最小可运行版本（MVP）**
   - 创建 `src/` 和一个最小入口（如 `main.py` / `index.ts` / `main.go`）
   - 确保可以通过 1 条命令运行
4. **同步补齐工程化基础**
   - 代码格式化与 lint
   - 单元测试框架
   - CI（至少包含 lint + test）
5. **发起第一个 PR**
   - 内容尽量小（例如“新增 Hello World + 基础测试”）
   - 在 PR 描述中写清：目标、改动、验证方式

## 推荐目录结构（初始化模板）

```text
limgene/
├─ src/                # 核心源码
├─ tests/              # 测试
├─ docs/               # 文档
├─ scripts/            # 开发与运维脚本
├─ .github/workflows/  # CI/CD
├─ README.md
└─ AGENTS.md           # 仓库内协作说明（可选）
```

## 新人前两周学习路线（建议）

### 第 1-2 天：看清全局
- 明确业务目标、输入输出、关键用户
- 了解团队协作方式（分支策略、PR 规范、发布节奏）

### 第 3-5 天：交付第一个可运行版本
- 完成最小功能闭环（哪怕很简单）
- 补上最基础测试
- 让 CI 跑通

### 第 2 周：提升质量
- 拆分模块，减少耦合
- 加入错误处理与日志
- 补充文档：开发说明、运行说明、常见问题

## 常见误区（避免踩坑）

- 一上来就追求“大而全”，导致迟迟没有可运行结果。
- 不写验证步骤，评审者无法快速复现。
- 不沉淀文档，后续协作成本快速上升。
